# 架构说明

本文说明 GSM01A（板卡 mc01a）固件的整体设计、模块职责、时序与资源占用。

---

## 一、系统分层

```
┌──────────────────────────────────────────────────────────────┐
│  应用层  Core/Src/main.c                                     │
│  初始化 · 线程创建 · 主循环喂狗 · TIM2 采样中断回调            │
├──────────────────────────────────────────────────────────────┤
│  业务模块层  App/                                             │
│  drv_ad7190 · alg_kalman · svc_hmi · drv_fram · drv_w25q64          │
│  svc_export   · bsp_board    · drv_tmc5240                           │
├──────────────────────────────────────────────────────────────┤
│  移植层  FATFS/ (App+Target)   USB_HOST/ (App+Target)         │
│          RT-Thread/rtconfig.h                                 │
├──────────────────────────────────────────────────────────────┤
│  中间件  Middlewares/                                         │
│  RT-Thread 内核 · FatFs R0.12c · ST USB Host Library (MSC)    │
├──────────────────────────────────────────────────────────────┤
│  驱动层  Drivers/STM32F4xx_HAL_Driver · Drivers/CMSIS         │
├──────────────────────────────────────────────────────────────┤
│  硬件  STM32F405RGT6 + AD7190 + FRAM + W25Q64 + HMI 屏 + U 盘 │
└──────────────────────────────────────────────────────────────┘
```

**分层原则**：业务模块只依赖 HAL 与 RT-Thread 的基础 API，不直接操作寄存器；CubeMX 生成的代码与自研代码通过 `USER CODE` 区块隔离。

## 二、模块职责

| 模块 | 文件 | 职责 | 关键接口 |
|---|---|---|---|
| `drv_ad7190` | `drv_ad7190.c/h` | AD7190 复位、寄存器读写、采样率设置、去皮、电源控制 | `drv_ad7190_init()` / `drv_ad7190_get_val()` / `get_tare_value()` / `sampling_rate()` |
| `alg_kalman` | `alg_kalman.c/h` | 一维标量卡尔曼滤波（Q=0.001, R=0.2） | `alg_kalman_init()` / `alg_kalman_calc()` |
| `svc_hmi` | `svc_hmi.c/h` | 串口屏通信、脚踏开关、下行命令解析、量程分挡、曲线换算 | `svc_hmi_tx()` / `svc_hmi_pedal_scan()` / `receive_data_parse()` |
| `drv_fram` | `drv_fram.c/h` | FRAM 读写 + 组/槽数据模型 + 环形缓冲重排 | `push_sample()` / `slot_flush_reorder()` / `user_switch_slot()` / `user_switch_group()` |
| `drv_w25q64` | `drv_w25q64.c/h` | W25Q64 读、写（自动扇区擦除）、4 KB 扇区擦除 | `w25q64_read()` / `w25q64_write()` / `w25q64_erase()` |
| `svc_export` | `svc_export.c/h` | FatFs 挂载/格式化、目录与文件创建、CSV 写入、目录递归清空 | `Mount_FatFs()` / `Create_File()` / `Save_Data()` / `Clear_File()` |
| `bsp_board` | `bsp_board.c/h` | 对外输出控制、LED 指示（低电平点亮） | `bsp_board_out1/2()` / `bsp_board_led1/2()` |
| `drv_tmc5240` | `drv_tmc5240.c/h` | TMC5240 32 位寄存器读写与初始化参数表（**预留，未启用**） | `drv_tmc5240_init()` / `tmc_test()` |

## 三、线程与同步

### 3.1 线程配置

| 线程名 | 入口 | 优先级 | 栈 | 节拍 | 说明 |
|---|---|---|---|---|---|
| `task_1` | `task1()` | 4（最高） | 1024 | 10 ms | 命令解析 + USB 轮询 |
| `task_2` | `hmi_uart()` | 10 | 1024 | 10 ms | 屏数据推送 |
| `task_3` | `get_data()` | 10 | 1024 | 信号量 | 数据换算与入缓冲 |
| `task_4` | `save_data_ing()` | 5 | 2048 | 100 ms | U 盘导出 |
| `pedal` | `pedal_thread_entry()` | 5 | 1024 | 10 ms | 脚踏扫描 |
| main | — | — | 4096 | 500 ms | 喂狗、LED、USB 轮询 |

RT-Thread 配置（`RT-Thread/rtconfig.h`）：`RT_TICK_PER_SECOND = 1000`、`RT_THREAD_PRIORITY_MAX = 32`、启用信号量与小型内存堆、`RT_MAIN_THREAD_STACK_SIZE = 4096`。

### 3.2 生产者 / 消费者

```
TIM2 中断（生产者）  ──rt_sem_release(dsem1)──▶  task_3（消费者，rt_sem_take 阻塞等待）
```

- 中断内完成 ADC 读取、零点扣除、均值/峰值策略、`x2` 赋值，随后释放信号量；
- `task_3` 被唤醒后完成单位换算、峰值更新、挡位判定、曲线换算与入缓冲。

### 3.3 采样节拍

| 参数 | 初值 | 运行值（`sampling_rate()` 之后） |
|---|---|---|
| TIM2 预分频 | 84-1（→ 1 MHz 计数） | 不变 |
| TIM2 重装载 | 999（→ 1 kHz 中断） | **9999（→ 100 Hz 中断）** |
| `it_count` | 100 | **10** |
| 输出节拍 | 100 ms | **100 ms（10 Hz 送屏）** |

即：**中断频率 = ADC 输出速率，累计 `it_count` 次后产出一个数据点。**

### 3.4 中断内信号处理策略（基线版本）

```c
v_data = drv_ad7190_get_val() - zero;

if (v_data < 阈值 && temp_val == 0)   mean_val += v_data;   /* 小信号 → 累加求均值 */
else if (v_data > temp_val)           temp_val = v_data;    /* 大信号 → 取最大值   */

if (++count1 >= it_count) {
    temp_val = (temp_val == 0) ? mean_val / it_count : temp_val;  /* 未超阈值取均值 */
    if (temp_val > 上限) temp_val = max_val;                       /* 超上限则保持 */
    x2 = temp_val;
    rt_sem_release(dynamic_sem_get);
}
```

**设计意图**：静息状态下取均值以抑制噪声；出现峰值时取最大值以保留瞬态响应。这是针对"力值曲线既有稳态也有尖峰"这一特征做的折中。

## 四、数据换算链路

| 环节 | 表达式 | 单位 | 说明 |
|---|---|---|---|
| ADC 原始值 | `drv_ad7190_get_val()` | 计数 | 24 位，增益 128（±39.06 mV 满量程） |
| 扣除零点 | `v_data = 原始值 - zero` | 计数 | `zero` 由去皮流程确定 |
| 节拍聚合 | `x2` | 计数 | 每 100 ms 一个值 |
| 力值换算 | `x1 = x2 / 100` | g | 基线版本（2025-11-19） |
| 力值换算（标定版） | `x1 = round(x2 / 109.635f) / 10` | g | 2026-04-07 版本，灵敏度 ≈ 1096 计数/g |
| 峰值保持 | `max_val = max(max_val, x1)` | g | 每次采集开始时清零 |
| 量程分挡 | 阈值 `{10,50,100,500,1000,3000}` g | 挡 1~7 | `calculate_shift()` |
| 曲线坐标 | 按挡位线性映射到 `0~150` | 像素 | `interval_conversion()` |
| 入环形缓冲 | `push_sample((int16_t)x1)` | g | 300 点 |

**量程分挡映射表**：

| 挡位 | 力值区间 | 曲线映射下限 | 满量程 |
|---|---|---|---|
| 1 | < 10 g | -1.5 g | 15 g |
| 2 | 10 ~ 50 g | -7.5 g | 75 g |
| 3 | 50 ~ 100 g | -15 g | 150 g |
| 4 | 100 ~ 500 g | -75 g | 750 g |
| 5 | 500 ~ 1000 g | -150 g | 1500 g |
| 6 | 1000 ~ 3000 g | -450 g | 4500 g |
| 7 | ≥ 3000 g | -750 g | 7500 g |

## 五、数据存储

### 5.1 三级模型

```
采样点 (300 点/槽, int16_t, 单位 g)
   │  push_sample() 环形写入
   ▼
槽 (20 槽/组)  ── slot_flush_reorder() 重排为线性 300 点 ──▶ FRAM 工作区 (12 KB)
   │  切换组时整组回写
   ▼
组 (100 组)  ──▶ W25Q64 SPI Flash (g × 12 KB, 共 1.2 MB)
   │  导出时读取
   ▼
U 盘 CSV (USB Host + FatFs)
```

### 5.2 环形缓冲重排

`push_sample()` 以环形方式写入 RAM 中的 300 点缓冲；落盘时 `slot_flush_reorder()` 按写指针重排为**线性时间序**，未满 300 点时补 0。这样既避免了每次写入都做数组搬移，又保证导出的数据顺序正确。

### 5.3 擦写策略

- **FRAM**：无擦除限制、写入快，作为"当前组"的读写缓存；
- **W25Q64**：`w25q64_write()` 内部**自动计算涉及的 4 KB 扇区并先擦除**，调用方无需关心擦除粒度；
- 组步长固定 12 KB，便于按索引直接定位。

## 六、USB 主机与文件系统

- **协议栈**：ST USB Host Library（`HOST_FS` 模式）+ MSC 类，支持 U 盘；
- **移植层**：`FATFS/Target/usbh_diskio.c` 把 USB MSC 块设备接入 FatFs；
- **容错**：`Mount_FatFs()` 在挂载失败且返回 `FR_NO_FILESYSTEM` 时，自动 `f_mkfs()` 格式化后重新挂载；
- **状态回调**：`USBH_UserProcess()` 维护 `Appli_state`（IDLE / START / READY / DISCONNECT），并驱动 LED1 指示 U 盘插入状态；
- **轮询**：`MX_USB_HOST_Process()` 需被周期性调用，当前在 `task_1`（约 1 s）、`task_4`（导出忙等）与 main 循环（500 ms）三处调用。

## 七、资源占用

以 2026-04-07 版本为例（Keil MDK 5.25 / ARMCC V5.06 update 6）：

```
Program Size: Code=45514  RO-data=1226  RW-data=332  ZI-data=37316

Flash: Code + RO-data + RW-data ≈ 47.1 KB / 1024 KB   (4.6%)
RAM:   RW-data + ZI-data        ≈ 37.6 KB / 128 KB    (29.4%)
```

RAM 主要消耗者：RT-Thread 内核对象与各线程栈（合计约 9 KB）、FatFs 工作区（`BYTE workBuffer[4*512]`）、`drv_fram.c` 的 `group_buf[300*20]`（12 KB，`int16_t`）、USB 主机栈缓冲。

## 八、代码组织约定

1. **CubeMX 用户代码区**：所有自研代码写在 `/* USER CODE BEGIN */ ... /* USER CODE END */` 内；
2. **模块命名**：`App/<前缀>_<对象>/<前缀>_<对象>.c/.h`，前缀取 `bsp_` / `drv_` / `alg_` / `svc_` 之一，目录名、文件名与标识符前缀三者一致（详见 README 3.2 节）；
3. **头文件依赖**：各模块 `.h` 只暴露必要的宏与函数原型，全局变量通过 `extern` 在 `.h` 中声明（如 `drv_fram.h` 暴露 `slot_t ram`）；
4. **源文件编码**：UTF-8 with BOM（中文注释）。`Drivers/` 与 `Middlewares/` 下的官方中间件保持原始编码。

## 九、扩展预留

工程中已实现但当前未启用的能力：

| 能力 | 现状 | 启用方式 |
|---|---|---|
| TMC5240 步进电机 | 驱动完整（寄存器读写 + 参数表 + `tmc_test()`） | 在 `main()` 中调用 `drv_tmc5240_init()`，并按需驱动 `M_EN` / `M_SLEEP` |
| RS485 通信 | USART2 已初始化，PA1 已分配为方向控制脚 | 在收发前后操作 `USART2_DE` 引脚 |
| USART3 通道 | 已初始化并开启中断 | 在 `stm32f4xx_it.c` 的中断处理中增加解析逻辑 |
| 对外数字输出 | `bsp_board_out1()` / `bsp_board_out2()` | 直接调用 |
| 可调采样率 | `sampling_rate()` 保留了 300 Hz ~ 4000 Hz 的配置分支（当前被注释） | 取消对应分支注释并放开入参覆盖 |
